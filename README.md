# أرشيف التحقيقات القيادية — FiveM RP

موقع عربي لتنظيم ملفات الشخصيات القيادية والقضايا والتقارير والمرفقات داخل سيرفر FiveM Roleplay.

> المشروع مخصص للعب الأدوار فقط، وليس نظامًا أمنيًا أو قانونيًا حقيقيًا.

## النسخة الثانية

- إنشاء ملف أساسي لكل شخص وتعديله أو حذفه.
- فتح عدة قضايا داخل ملف الشخص، مع تعديل القضية أو حذفها.
- تقرير قضية جاهز ومنظم يشمل الملخص، الادعاءات، الإفادات، الإجراءات، النتائج، القرار والتوصيات.
- طباعة تقرير القضية مباشرة أو حفظه PDF من نافذة الطباعة.
- رفع الصور والفيديوهات والمستندات والملاحظات إلى القضية.
- تعديل وصف المرفق أو حذفه.
- قفل ملف الشخص برمز اختياري يختاره مدير الملف.
- وضع نهاري ووضع ليلي، مع حفظ الاختيار في المتصفح.
- تصميم عربي متجاوب مع الكمبيوتر والجوال.
- فحص تلقائي لملفات JavaScript قبل كل نشر على GitHub Pages.

## تنبيه عن قفل الرمز

قفل الرمز في النسخة الحالية هو **قفل داخل واجهة الموقع** لمنع الفتح العرضي. ليس تشفيرًا للبيانات، ولا يعوض تسجيل الدخول والصلاحيات وقاعدة البيانات المحمية عند الاستخدام الحقيقي.

## الوضع التجريبي الحالي

`config.js` يشغّل الوضع التجريبي افتراضيًا. في هذا الوضع تُحفظ الملفات والبيانات داخل متصفح الجهاز باستخدام IndexedDB، ولذلك:

- لا تنتقل البيانات تلقائيًا إلى جهاز آخر.
- مسح بيانات المتصفح قد يحذف الأرشيف المحلي.
- الملفات الكبيرة تعتمد على مساحة التخزين المتاحة في المتصفح.

## التشغيل المحلي

```bash
python -m http.server 8080
```

ثم افتح:

```text
http://localhost:8080
```

## ربط Supabase

للاستخدام المشترك وتسجيل الدخول والحفظ الدائم:

1. أنشئ مشروعًا في Supabase.
2. للمشروع الجديد شغّل `supabase/schema.sql`.
3. إذا سبق أن شغّلت النسخة الأولى، شغّل `supabase/migration_v2.sql` بدل إعادة إنشاء الجداول.
4. أنشئ المستخدم الأول من Authentication ثم أضفه إلى جدول `profiles` بدور `admin`.
5. عدّل `config.js` واجعل `demoMode: false` وأضف رابط Supabase و`anon key` فقط.

لا تضع مفتاح `service_role` داخل الموقع.

## النشر

ملف `.github/workflows/deploy-pages.yml` يفحص التطبيق ثم ينشره تلقائيًا على GitHub Pages عند كل تحديث لفرع `main`.
