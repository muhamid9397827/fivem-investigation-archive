# أرشيف التحقيقات القيادية — FiveM RP

موقع عربي من اليمين إلى اليسار لتنظيم ملفات الشخصيات القيادية، القضايا، الصور، الفيديوهات، المستندات والملاحظات الخاصة بسيرفر FiveM Roleplay.

> هذا المشروع مخصص للعب الأدوار فقط، وليس نظامًا أمنيًا أو قانونيًا حقيقيًا.

## الموجود في النسخة الحالية

- لوحة تحكم وإحصاءات.
- بحث بالاسم أو الرقم العسكري.
- إنشاء ملفات أشخاص وقيادات.
- إنشاء عدة قضايا داخل ملف كل شخص.
- إضافة صورة أو فيديو أو مستند أو ملاحظة لكل قضية.
- حالات للقضايا والأولوية وحالة الشخص.
- تسجيل دخول وصلاحيات عند ربط Supabase.
- وضع تجريبي كامل يحفظ البيانات والملفات داخل متصفحك باستخدام IndexedDB.
- نشر مباشر على GitHub Pages دون تثبيت أي حزم.
- فحص آلي لسلامة ملفات JavaScript قبل كل عملية نشر.

## التشغيل على جهازك

لا يحتاج الموقع إلى Node.js أو تثبيت حزم.

يمكنك فتح `index.html` مباشرة، والأفضل تشغيل خادم محلي بسيط من داخل مجلد المشروع:

```bash
python -m http.server 8080
```

ثم افتح:

```text
http://localhost:8080
```

الوضع التجريبي مفعّل افتراضيًا من `config.js`.

## بنية ملفات الواجهة

ملفات التصميم والتطبيق موجودة داخل مجلد `webparts`. تُجمع تلقائيًا في المتصفح بواسطة `webparts/loader.js`. استُخدمت هذه البنية لتبقى النسخة ثابتة وسهلة النشر على GitHub Pages دون نظام بناء أو حزم خارجية.

## الانتقال إلى النظام الحقيقي المشترك

1. أنشئ مشروعًا في Supabase.
2. افتح SQL Editor وشغّل الملف `supabase/schema.sql` كاملًا.
3. أنشئ أول مستخدم من Authentication > Users.
4. انسخ UUID الخاص بالمستخدم، ثم نفّذ أمر إضافة المدير الموجود في آخر ملف SQL.
5. عدّل `config.js`:

```js
window.APP_CONFIG = {
  demoMode: false,
  supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
  supabaseAnonKey: 'YOUR_ANON_KEY',
}
```

6. افتح الموقع وسجّل الدخول بالبريد وكلمة المرور اللذين أنشأتهما في Supabase.

## النشر على GitHub Pages

1. من Settings > Pages اختر GitHub Actions كمصدر النشر.
2. ادفع الملفات إلى فرع `main`.
3. ملف `.github/workflows/deploy-pages.yml` يفحص ملفات التطبيق ثم ينشر الموقع تلقائيًا.

يمكن إبقاء `demoMode: true` لعرض نسخة تجريبية. للاستخدام الجماعي الحقيقي عدّل `config.js` واربط Supabase قبل النشر.

## ملاحظات أمنية

- لا ترفع أي ملفات قضية فعلية إلى مستودع GitHub؛ الملفات تُرفع إلى Supabase Storage فقط.
- لا تستخدم مفتاح `service_role` داخل `config.js` أبدًا. استخدم `anon key` فقط.
- الحماية الفعلية تعتمد على سياسات Row Level Security الموجودة في `supabase/schema.sql`.
- مساحة `case-evidence` خاصة، والملفات تظهر بروابط مؤقتة موقعة.
- النسخة التجريبية محلية وليست مناسبة للعمل من عدة أجهزة.

## المرحلة التالية المقترحة

- تعديل وحذف الملفات والقضايا.
- سجل نشاط كامل لكل تعديل.
- إدارة المستخدمين والصلاحيات من داخل الموقع.
- تصدير القضية إلى PDF.
- اعتماد القرار من القيادة وإضافة تعليقات داخلية.
